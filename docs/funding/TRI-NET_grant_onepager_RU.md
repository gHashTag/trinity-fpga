# TRI-NET: открытая инфраструктура конформности числовых форматов

**Грантовый one-pager (черновик для подачи).** Автор: Vasilev (gHashTag), ORCID 0009-0008-4294-6159, admin@t27.ai. Лицензия всего задела — Apache-2.0.
Дата: 2026-07-30. Версия: v0.1.

> One-line: **не «новый формат чисел», а open-source-инфраструктура для проверки любых низкоточных форматов (FP8/MX/NF4/posit/takum/собственных) — от каталога-SSOT до RTL-оракулов и измерений на кремнии.**

---

## 1. Что это

Линейка из четырёх проектов (**TRI-NET**: Phi, Euler, Gamma, Corona) + форматный каталог-SSOT (`gHashTag/t27`, 80 форматов в 13 семействах) + toolchain, который генерирует из единого источника (SSOT) код на 17 языках, включая **Verilog-ROM оракул конформности**. Стержневой репозиторий-актив: `gHashTag/trinity-fpga` — FPGA-измерения конформности на реальном кремнии (Artix-7 AX7203).

Это **не очередной ML-ускоритель и не претендент на превосходство над IEEE/posit/takum**. Это инструментальная инфраструктура: каталог + эталонные декодеры + машина проверки.

## 2. Статус (честно, по статус-тегам)

| Актив | Статус | Что есть реально |
|-------|--------|------------------|
| Форматный каталог-SSOT (80 форматов) | `[Verified]` | `t27` PR #1028, механическая codegen-цепочка |
| RTL-декодеры Corona (17 модулей, 18 семейств) | `[Verified SW]` | exhaustive-симуляция, 592 308 кодов |
| Верификация Corona — 5 слоёв | **4/5 в SW/GDS** | exhaustive + independent reference + formal (SymbiYosys) + GDS-precheck PASS. **5-й слой (измерения на кристалле) НЕ исполнен — кремний отменён** |
| Кремний TRI-NET (Phi/Euler/Gamma/Corona, TinyTapeout GF180MCU/SKY130A) | `[Отменён]` для Corona; остальные — `[Empirical fit]` | RTL и GDS готовы; **кристалла Corona не будет**. Импакт формулируется от RTL+методологии, а не от чипа |
| FPGA-conformance на AX7203 (trinity-fpga) | `[Измерено на FPGA]` | реальные UART-прогоны @160000, IDCODE 0x13636093 — это **фактический silicon-задел** (на FPGA, не ASIC) |
| Научная претензия «FL-002: phi-ladder breadth-as-moat» | `[Открытая гипотеза]` | **не доказана**; takum (Hunhold 2024) — стоящий counterexample, честно отгружается в каталог, не подавляется |

**Главное honesty-правило для заявки:** нигде не утверждать превосходство «золотых форматов» над конкуренты — претендовать только на **breadth + toolchain-coherence + методологию конформности**.

## 3. В чём реальная ценность (для ревьюера)

1. **End-to-end механическая цепочка SSOT → codegen → RTL → (измерение)**: один источник → 17 выходных языков → верифицируемый RTL. Это инженерно-методологический вклад, воспроизводимый независимой командой.
2. **Многомаштабная верификация декодеров**: exhaustive-разведение + независимый reference + formal + mutation-kill. Применима не только к нашим форматам — к любым (FP8, OCP MX, posit, takum).
3. **FPGA-conformance как реальный Tier-E задел**: `trinity-fpga` уже измеряет десятки форматов на AX7203 бит-в-бит — это рабочий полигон для проверки низкоточных арифметик.
4. **Открытая референсная база для research**: 80-форматный каталог + эталонные оракулы как датасет/бенчмарк.

## 4. Что даёт грант (задел → результат)

- **Доводка 5-го слоя верификации** (post-silicon): перенос RTL-декодеров на FPGA-полигон AX7203 для измеримого бит-экзацепта → закрытие методологической цепочки 5/5 на доступном кремнии (FPGA).
- **Conformance-SDK**: упаковка каталога + оракулов в библиотеку/CLI для ML-команд, внедряющих квантизацию (FP8/MX/NF4) — аудит корректности декодеров.
- **Публикации/артефакты**: методологическая статья + воспроизводимые FPGA-результаты.

## 6. Монетизация (честно: не SaaS)

Лицензия Apache-2.0 и принцип «NOT closed-IP» исключают продажу чипа/IP как монополии. Реалистичная модель — **open-core + платный сервис**:
- **Открытое ядро** (каталог, оракулы, RTL) — бесплатно, Apache-2.0.
- **Платные аудит/интеграция** для ML-команд: проверка их декодеров FP8/MX/NF4 против эталонов, кастомные low-precision IP-блоки для FPGA/ASIC, консалтинг по квантизации. Модель Tidelift/консалтинга, не подписка.
- Узкий рынок (крупные игроки имеют свои golden-декодеры) → ниша = средние ML-команды и ASIC/FPGA-стартапы.

**Caveat:** коммерческий moat здесь — ширина toolchain'а и методология, **не** превосходство формата (FL-002 = `[Открытая гипотеза]`).

## 7. Риски и оговорки

- **Кремний отменён** → нельзя претендовать на «чип на руках». Импакт строго от RTL/методологии/FPGA-измерений.
- **4/5 слоёв верификации в SW** → формулировать как методологию, не как «доказано на кристалле».
- **FL-002 не доказана** → никаких «лучше posit/takum» в заявке.
- **Рынок conformance-аудита узок** → гранты (не продукт) — основной ближний деньги.
