# Три дефекта на ступени GF-T32, найденные 8 августа 2026

Все три независимы, все три на одной ступени, и любой из них в одиночку испортил бы подачу. Плюс отдельно — установленный факт про оракул конкурента.

---

## 1. Оракул `gft_ref.py` переворачивает знак

```
GF-T32 (Et=6, M=25):  encode(1.5) → decode → −1.5
                      encode(100) → decode → −100
```

Локализовано: **зависит от ширины мантиссы, не от числа тритов.**

| | M=9 | M=21 | M=25 | M=52 |
|---|---|---|---|---|
| Et=4 | OK | **ЗНАК** | **ЗНАК** | OK |
| Et=5 | OK | **ЗНАК** | **ЗНАК** | OK |
| Et=6 | OK | **ЗНАК** | **ЗНАК** | OK |
| Et=7 | OK | OK | **ЗНАК** | OK |

Похоже на ошибку позиции знакового бита при определённых суммарных ширинах.

**Почему это важно:** записка `GF_T_GOLD_STANDARD_LADDER` утверждает «One oracle covers every rung; all pass add/mul commutativity [measured]». Коммутативность сложения и умножения **не ловит переворот знака** — если знак инвертирован у обоих операндов последовательно, a+b всё равно равно b+a. Проверка была настоящей, но слепой именно к этому классу дефекта.

**Проверка, которая ловит:** round-trip `encode → decode` на 1.0 / 1.5 / 100.0. Тривиальная, три строки.

```python
F = gft.GFTFormat(6, 25)
assert float(gft.decode(F, gft.encode(F, 1.5))) == 1.5   # падает
```

## 2. RTL `gft_mul.v` усекает произведение

`wire [31:0] prod` при `MANT_ONE = 2²⁵` ⇒ произведение 52 бита, верхние 20 отбрасываются. **1 995 730 расхождений из 2 128 964** против `gft_mul32.v`.

Шапка модуля называет GF-T32 поддерживаемой конфигурацией, поэтому подстановка параметров выглядит законной. Исправлено в `gft_mul_w.v` (ширины выводятся из параметров), PR trinity-fpga#510.

## 3. Параметры GF-T32 противоречат сами себе

В одном документе `GF_T_GOLD_STANDARD_LADDER_2026-08-05.md`:

- таблица кремния: **Et=6, M=25**
- таблица оракула, 14 строк ниже: **Et=5, M=21**

RTL (`OFFSET_MAX = 728 = 3⁶−1`, `MANT_ONE = 2²⁵`) соответствует первой. И заметь: **обе «плохие» ширины мантиссы из дефекта №1 — это ровно 21 и 25**, то есть оба варианта спорной спецификации попадают в сломанный диапазон оракула.

Плюс `gft_add64.v` несёт `OFFSET_MAX = 19682 = 3⁹−1` (девять тритов), а лестница даёт GF-T64 семь.

## 4. Оракул tekum — это takum, побитово

Проверено исчерпывающе: **все 65 536 кодов** 16-битного пространства декодируются `tekum_ref.py` и `takum_ref.py` **одинаково, 0 различий**. Реализации различаются на 242 строки, поведение совпадает полностью.

**Следствие:** каждое заявление «GF-T16 обходит tekum16» фактически означает «обходит **takum16**». Это не ослабляет результат — takum опубликован, известен, и у него есть настоящий VHDL-кодек, так что как якорь он даже лучше малоизвестного потомка. Но называть надо правильно.

## 5. Провенанс 323 МГц — закрыт

Из твоей же записки `XC7A200T_GF16_DATAPOINT_2026-08-05.md`:

> «The paper's headline 323 MHz is the **combinational** max-frequency of the bare `gf16` core, measured against a ripple-counter probe clock (`Max frequency for clock 'chain[19]': 323.31 MHz`).»

`chain[19]` — это кольцевой генератор из 20 инверторов, который я нашёл в топе. То есть 323 МГц — это `1 / (комбинационная задержка)`, снятое через пробник, **а не частота регистр→регистр**. Разведённый тактируемый конформанс-дизайн даёт **27.55 МГц**.

И деталь названа тремя разными способами: **XC7A35T** в абстракте arXiv:2606.05017, **XC7A100T** в теле `trinity-gf16.tex`, **XC7A200T** в воспроизведении от 5 августа.

Мои конвейерные измерения GF-T (12/50/212/1477 LUT при 161/153/132/83 МГц) — первые честные частоты регистр→регистр для этого семейства.
